# 食刻 · shike

**在线使用：[jinguo1627-svg.github.io/shike](https://jinguo1627-svg.github.io/shike/)** —— 手机打开后「添加到主屏幕」，就是一个可离线用的 App。

离线优先的食物热量记录器。打开就是「今天还能吃多少」，记完自动算三大营养素，数据只存在你自己的设备上。

PWA 形态，一套代码跑在手机浏览器和桌面，可添加到主屏幕当原生 App 用。

## 它做什么

- **今日进度环**：剩余热量一眼可见，超出目标时环变红并显示超出量
- **份量换算**：支持克数与「一碗 / 一个 / 一片」等家常份量，两套口径随时切换
- **三大营养素**：蛋白 / 脂肪 / 碳水 分别对照目标，进度条实时更新
- **按餐次记录**：早 / 午 / 晚 / 加餐，每餐小计
- **目标管理**：Mifflin-St Jeor 算基础代谢，按活动量与减脂/增肌目标推算每日热量与配比
- **7 日趋势**：柱状图对照目标线，含日均、未超目标天数
- **自定义食物**：家常菜没有标准数据，按自己的配方建一条
- **导出 / 导入备份**：JSON 全量备份，换设备或浏览器清数据后可恢复
- **完全离线**：Service Worker 预缓存，断网可用，代码里没有一处网络请求

## 功能等级

按「有没有目标—进度—反馈闭环」划分，本项目定位 **L3（管理级）**：

| 等级 | 门槛 | 本项目 |
| --- | --- | --- |
| L0 手动级 | 热量全靠手输 | — |
| L1 查询级 | 有内置食物库 | ✅ 179 条 |
| L2 记录级 | 关掉再开记录还在 | ✅ IndexedDB |
| L3 管理级 | 主动告诉你「今天还剩多少」 | ✅ 进度环 + 目标 + 趋势 |
| L4 专业级 | 能替代一次营养咨询 | ❌ 不做，见「边界」 |

## 技术栈

React 19 + TypeScript + Vite 8，本地存储 Dexie（IndexedDB），PWA 用 vite-plugin-pwa。
**零运行时依赖之外的东西**：没有 UI 库、没有图表库、没有状态管理库——环形进度和柱状图都是手写 SVG。

生产包 **115 KB（gzip）**，首屏无需二次请求。

## 几个关键设计决策

**1. 目标是分版本的，不是存在档案里的一个数字。**
用户把目标从 1800 改成 1600，如果直接改档案字段，昨天那条「还剩 200」会变成「还剩 0」——历史被篡改。所以 `targets` 表带 `effectiveFrom`，查某天的目标 = 「取生效日期 ≤ 该天的最后一条」。

**2. 一天从 4 点开始。**
凌晨 1 点吃的夜宵算前一天。按自然日切分会把一天拆成两半，让每天的对比失真。这个小时数可在设置里改。

**3. 记录存的是营养快照，不是食物引用。**
每条记录写入时把热量与三大营养素算好存下来。之后改食物库数据，历史记录不会跟着变——这对「历史就是历史」的记录类应用是必需的。

**4. 食物数据用 4/9/4 法则自检。**
`tests/data.test.ts` 对 179 条逐条反算：蛋白×4 + 碳水×4 + 脂肪×9 与标称热量的偏差必须 <35%（酒精类按 7 kcal/g 单独排除）。数据打字打错会直接让 CI 挂掉。

**5. 营养学口径写死成常量，不猜。**
减脂缺口上限 750 kcal/日、增肌盈余上限 500、女性下限 1200 / 男性 1500、蛋白按 1.4–1.8 g/kg 体重。低于下限时目标被上调并在界面上标注「已触及安全下限」。

## 部署

构建产物是纯静态文件，`base` 已设为相对路径，可直接部署到任何静态托管：

```bash
npm run build
# 把 dist/ 上传即可
```

GitHub Pages：推到 `gh-pages` 分支或在仓库 Settings → Pages 选择 GitHub Actions。
Vercel / Netlify：连仓库，构建命令 `npm run build`，输出目录 `dist`。

Service Worker 需要 HTTPS（`localhost` 例外），上述平台默认提供。

## 边界与免责

- 食物数据取常见品种均值，同种食物因产地、部位、烹饪方式不同会有 **±20% 波动**；一餐的估算误差轻松到 ±25%。这里给的是区间感，不是仪器读数。
- 不提供医疗建议，不做疾病干预。**孕期、慢性病（肾病限钾限磷、糖尿病、痛风）、进食障碍人群请遵医嘱**，本工具不适用。
- 不做 L4 的事：没有微量元素库、没有可食部系数、没有等热量替换建议。原因不是不会写，是那三样需要权威数据授权与营养师背书。

## 隐私

数据全部存在浏览器 IndexedDB，没有账号、没有同步、没有埋点、没有网络请求。
设置页提供「删除全部数据」，可彻底清除记录、目标、身体数据与自定义食物。

但 **iOS 可能在存储压力下清理站点数据**——「导出备份」是唯一可靠的兜底，建议定期导一份。
另外，GitHub Pages 的 `用户名.github.io` 是单一 origin，同一账号下的其他项目页面与本应用共享存储空间；如果在意这一点，请部署到独立域名或 `*.pages.dev` 子域。
